Clusters for HelloKahwin

This builds on HelloKahwin's existing pillar and cluster system. Today, pillars and clusters are categories, set up once by a script, and every article links back up to its pillar. Nothing new competes with that system. This adds the parts that are missing: a place to manage clusters, a box on each article listing the rest of its cluster, a clear way to put an article in a cluster, and per-cluster numbers.

In plain words: after this, you can open an admin page and see every cluster (for example "Mas kahwin ikut negeri") with its articles, which are live, which are drafts, how many views each got, and which clusters are thin. Readers on an article see a "Dalam siri ini" box near the top linking to the other guides in the same cluster.

What gets built

1. Clusters admin page (new, English)

  • A new "Clusters" tab in the Inspire admin. Shows every pillar and, under it, each cluster with its counts (live, draft or scheduled), last published date, and page views over the last 28 days.
  • Opening a cluster shows its articles with status, publish date and 28-day views. It warns about clusters with fewer than 3 live articles and pillar articles that aren't in any cluster.
  • You can edit a cluster's or pillar's linking phrase, pillar intro and series-box description, turn the series box on or off, and add a new cluster under a pillar.

2. "Cluster" picker in the article editor

  • One clear dropdown to put an article in a cluster. An article belongs to one cluster at most, and choosing one replaces the old one. It shows which pillar the cluster sits under.

3. "Dalam siri ini" box on articles (public, Malay)

  • Appears near the top of an article when its cluster has the box switched on and at least one other live article. The title is the cluster's Malay linking phrase, then an optional short description, then up to 8 sibling guides. The current article is marked but not linked. A last link goes to the pillar page.
  • One column on phones, two on wider screens. No extra images. Built for low-end Android, like the rest of the site.
  • Off by default for every cluster, so nothing changes for readers until you switch a cluster on.

Deliberately not included

  • TWN's separate "series" tables. HelloKahwin keeps one cluster system, its categories.
  • Search Console clicks and positions inside the admin. That's a follow-up; this version shows site page views.
  • Ordering a cluster's articles by hand. Siblings are listed newest first.
  • The /cluster writing workflow. That's the next, separate job: reviewing it and adapting it for HelloKahwin.

Technical notes

  • Data: one additive migration on inspire_categories: series_enabled boolean NOT NULL DEFAULT false and series_description text. It follows the repo's migration convention and is applied by hand at ship time. HelloKahwin has one database (production); the change is additive and off by default, so it's safe to apply before the deploy.
  • Reuse: pillar-queries.ts (getPillarUpLink, getClusterSiblings, categoryAnchor), the categories admin actions and audit pattern, and the cache tags articles / inspire-categories. The article page's withDeadline/budgetLeft fallback pattern means the box is non-critical: on a timeout the article still renders.
  • Security: every new server action goes through the same admin-allowlist check the existing Inspire actions use. Inputs are validated with zod, and the description is plain text capped at 600 characters.
  • Analytics: 28-day views come from analytics_events using the existing pathname+created_at index. Each panel has a time limit and shows an empty state rather than breaking the page.
  • Checks: unit tests for the queries, actions (auth, validation, one-cluster rule), series box rendering (off, on, too few siblings, current marked) and editor picker. Before review, the full repo gate on the final HEAD: pnpm test && pnpm typecheck && pnpm lint.
  • Order: migration and schema → queries → admin page and actions → editor picker → public box → tests → full gate → one Codex review → local preview for Ian → /imdone. It stops at the queue; shipping is Ian's call.
