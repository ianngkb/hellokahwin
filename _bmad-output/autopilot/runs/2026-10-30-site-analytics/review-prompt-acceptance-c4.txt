# Spec — HelloKahwin Site Analytics (first-party, no rollups)

**Branch:** `ianng89/hellokahwin-site-analytics`
**Date:** 2026-10-30
**Status:** auto-accepted (autopilot Phase 2, one-spec rule)
**Memlog:** `_bmad-output/specs/spec-hellokahwin-site-analytics/.memlog.md`

---

## Why

hellokahwin.com has no analytics at all: no GA tag, no first-party collector, no tables. The only trace is `src/lib/analytics/tracker.ts`, a no-op `track()` seam ported from twn-new with one live caller (`photo-gallery.tsx:197`). The owner runs the site on data (traffic, acquisition, which Malay wedding content lands) and currently reads none of it. twn-new already carries a proven first-party pipeline (collector, privacy model, bot flagging, admin dashboard); this work ports it, stripped of twn-new's rollup machinery and business-specific panels, because commit `4e8aaaf` removed every scheduled job from hellokahwin on purpose and nothing scheduled may return. There is no historical first-party data, so this is a clean build with nothing to backfill.

## Capabilities

- **CAP-1 Event collection endpoint**
  - **intent:** The public site can POST a batch of analytics events to `/api/v1/analytics/collect` and have each one stored as a row in `analytics_events`, enriched server-side (hash, geo, device, bot flag).
  - **success:** A valid batch of N events returns `200 {success:true,data:{accepted:N}}` and N rows exist; malformed JSON or a body failing the schema returns 400; more than 120 requests/min from one IP returns 429; a DB stall returns 503 `analytics_unavailable` within ~8s instead of hanging.

- **CAP-2 Client tracker with preserved `track()` seam**
  - **intent:** Every page in the `(public)` route group records a `pageview` on load and on every App Router pathname change, and any code calling the existing `track(event, props)` records a custom event, with no change at call sites.
  - **success:** `track()` keeps the signature `(event: string, props?: Record<string, unknown>) => void`; the photo-gallery call site is untouched and `Photo Gallery Opened` rows appear with `props.photo_count`. No pageview fires from `/admin/*`, `/login`, `/no-access`, `/draft/*` (token preview), the `(admin-preview)` or `(print)` route groups, or from a framed render. Events are batched and flushed every 5s and on `visibilitychange: hidden` via `sendBeacon`.

- **CAP-3 Anonymous visitor identity, privacy-parity with twn-new**
  - **intent:** Visitors are counted uniquely per day without storing anything that identifies a person.
  - **success:** No column holds a raw IP. `visitor_hash` = sha256(`ip|ua|<KL yyyymmdd>|ANALYTICS_SALT`). `visitor_id` is read only from the first-party `_hk_vid` cookie (UUID, 2 years, `Path=/; SameSite=Lax; Secure` on https, not httpOnly), never from the payload; absent or malformed cookie stores NULL and the row is still written. A missing `ANALYTICS_SALT` yields 503 and an error log, never an unsalted hash.

- **CAP-4 Bot rows kept but flagged**
  - **intent:** Bot traffic is recorded for inspection but excluded from every dashboard number by default.
  - **success:** The collect route classifies the request UA with the ported `bot-list.ts` and stores `is_bot` + `bot_reason`. The dashboard defaults to humans and offers a Humans / Bots / All toggle whose labels show distinct-visitor counts per bucket; switching modes changes every panel.

- **CAP-5 Geo from Vercel request headers**
  - **intent:** Each event carries country, state code, city, latitude and longitude as Vercel resolved them, with no dataset lookups.
  - **success:** `x-vercel-ip-country`, `x-vercel-ip-country-region` (normalised to 1–10 upper-case alphanumerics or NULL), `x-vercel-ip-city` (percent-decoded), `x-vercel-ip-latitude/longitude` populate the row; `cf-ipcountry` is the country-only fallback; local dev stores NULLs. No `cities15k.json` and no city/region estimation exist in the repo.

- **CAP-6 Top stats with previous-period comparison**
  - **intent:** An admin sees unique visitors, visits, pageviews, views/visit, bounce rate and average visit duration for the selected KL date range, each with a change badge against the preceding range of equal length.
  - **success:** Six tiles render; each badge compares against `getPreviousPeriod(from, to)`; definitions match twn-new (visit = session; bounce = single-pageview session; duration = session span capped at 1800s, over sessions with >1 pageview; unique visitors = distinct `visitor_hash` over rows, not over sessions).

- **CAP-7 Time-series chart**
  - **intent:** The same six metrics are plotted per KL day across the range, switchable by tile.
  - **success:** Clicking a stat tile re-plots the area chart; days are bucketed with `DATE(created_at AT TIME ZONE 'Asia/Kuala_Lumpur')`; an empty range renders an empty state, not a crash.

- **CAP-8 Acquisition panels**
  - **intent:** Admin sees where visitors come from: referrer host, UTM medium, UTM campaign.
  - **success:** Three tables of top 20 by distinct visitors with percentage share. Referrer host is derived as twn-new does (`Direct / None` for empty; strip scheme and `www.`; keep host only). Empty UTM buckets as `(none)`. UTM params are captured once per page load from the landing URL.

- **CAP-9 Content panels with resolved titles and page filter**
  - **intent:** Admin sees top, entry and exit pages, reads article titles rather than slugs, and can scope the whole dashboard to one pathname.
  - **success:** Top pages count distinct visitors per `pageview` pathname; entry/exit pick the first/last pageview per session (`DISTINCT ON (session_id)`, session-less rows excluded). Pathnames resolve to titles for `/` (Laman Utama), `/artikel` (Semua Artikel), `/artikel/<category>` (category name), `/artikel/<category>/<slug>` (article title), `/artikel/tag/<slug>` (tag name), `/artikel/author/<slug>` (author name), `/brand`; unresolved paths show the raw path. A page-search box (debounced, ILIKE on pathname within the range) sets `?page=` and every panel honours it.

- **CAP-10 Geo drill-down: countries → states → cities**
  - **intent:** Admin can click a country to scope the dashboard to it, then a state to scope further, and see cities under the current scope.
  - **success:** `?country=` is validated to a real ISO alpha-2 (provider pseudo-codes `XX ZZ EU AP QO A1 A2 O1 T1` rejected); `?region=` only honoured with a country. Countries table stays global; States table is scoped to the country but not the region (navigator rule); Cities honours both. Malaysian state codes render as names from a static ISO 3166-2:MY map (e.g. `10` → Selangor); any other code renders raw. Country names come from `Intl.DisplayNames`.

- **CAP-11 Technology panels**
  - **intent:** Admin sees browsers, operating systems and screen-size buckets.
  - **success:** Browser and OS are parsed server-side from the UA with `ua-parser-js` at collect time; screen buckets are Mobile (<768), Tablet (<1024), Desktop, Unknown from `screen_width`. Humans vs bots counts appear in the toggle (CAP-4).

- **CAP-12 KL date-range picker**
  - **intent:** Admin picks a range in Asia/Kuala_Lumpur calendar days via URL params.
  - **success:** `?from=yyyy-MM-dd&to=yyyy-MM-dd`, default last 30 days ending KL today; presets (Today, 7d, 30d, 90d, This month, Last month); two native date inputs for custom; invalid or rolled-over dates fall back; `to` clamps to today; range longer than 366 days clamps to 366. Queries compare the bare `created_at` column against half-open UTC instants derived from the KL days (`[from 00:00+08, to+1 00:00+08)`).

- **CAP-13 Admin navigation entry**
  - **intent:** Admin can reach the dashboard from the console chrome.
  - **success:** `ADMIN_NAV_GROUPS` gains an `analytics` group (icon `BarChart3Icon`, tab "Site analytics", href `/admin/site-analytics`, keywords `traffic pageviews visitors referrers utm countries browsers`), so it appears in the sidebar, the group tab bar and the ⌘K palette.

- **CAP-14 Additive schema migration with RLS**
  - **intent:** The `analytics_events` table exists in prod with the same protections as every other public-schema table.
  - **success:** `src/lib/db/schema/analytics-events.ts` is exported from the schema index; migration `0005_analytics_events.sql` (plus `meta/_journal.json` and snapshot entries) creates the table, its indexes and `ALTER TABLE "analytics_events" ENABLE ROW LEVEL SECURITY;` with no policies. Nothing is altered or dropped.

- **CAP-15 Dashboard fast without rollups**
  - **intent:** The admin page renders in bounded time by reading `analytics_events` directly.
  - **success:** Every getter is date-bounded and index-sargable; results are wrapped in `unstable_cache` (tag `site-analytics`, `revalidate: 600`, args in key); the cold fan-out runs through `runBatched(…, 4)`; each panel goes through the existing `safePanel` (6s deadline, degrade to empty on transient DB errors). A single failing panel never 500s the page.

## Constraints

- **No cron, no scheduled job, no GitHub Action, no Vercel cron entry.** Rollup tables, rollup refresh, retention sweeps and health checks from twn-new are out. Anything periodic is a follow-up requiring an owner decision.
- **Additive-only migration**, hand-numbered `0005_…`, applied with `pnpm db:migrate`; RLS enabled on the new table with zero policies (matches `0001`). The app connects as `postgres` via the transaction pooler, so RLS costs nothing at runtime.
- **Privacy:** no raw IP anywhere; salted daily hash; cookie is anonymous and first-party; `user_agent` is stored (parity with twn-new, enables later re-classification).
- **`track()` signature unchanged**; `src/lib/analytics/tracker.ts` stays the import path.
- **Public bundle budget:** the client tracker adds no third-party dependency (UA parsing is server-side); only `screen_width` and pathname/referrer/UTM leave the browser.
- **Pageviews only on `(public)`**; the tracker component is mounted in `src/app/(public)/layout.tsx` as a `<Suspense>` sibling of `{children}` (never a wrapper, so `notFound()` keeps producing real 404s) and returns early when the pathname starts with `/draft/`.
- **Collect route stays outside the Clerk matcher** (`isClerkRoute` lists only `/api/v1/inspire`); do not add it. Rate limiting is per-IP in-memory (port twn-new's `ipRateLimit` to `src/lib/api/rate-limit.ts`), `maxDuration = 15`.
- **`ANALYTICS_SALT`** is a new required env var (`.env.example` + Vercel production/preview) and must exist before the deploy that enables collection.
- **Admin UI is English**; public-facing title resolution uses the site's Malay labels where a static route has one.
- **Reuse before port:** `safePanel`, `withDeadline`, `isTransientDbError`, `apiSuccess/apiError`, `ConsoleTable`, `EmptyState`, `StatCard`, `SectionCard`, the admin `PageHeader` and skeleton primitives already in hellokahwin are used as-is.
- **Dependencies added:** `recharts`, `ua-parser-js` (+ `@types/ua-parser-js`). Not added: `iso-3166-2`, `react-day-picker`.
- **Timezone:** all day bucketing, the default range and the hash rotation use Asia/Kuala_Lumpur; the collect route computes the KL day with `toLocaleDateString('en-CA', { timeZone: 'Asia/Kuala_Lumpur' })`.
- **Query discipline:** compare the bare `created_at` column to bound parameters; never wrap the column in `AT TIME ZONE` inside a WHERE clause. Top-stats reads the scoped rows once (`WITH scoped AS MATERIALIZED`).

## Non-goals

- Rollup tables (`analytics_visitor_daily`, `analytics_session_daily`, `analytics_visitor_target_daily`, `analytics_rollup_days`) and `rollup-refresh.ts`.
- City or region estimation from coordinates (`city-estimate.ts`, `cities15k.json`, backfill scripts).
- 404 capture route and table, `not-found-tracker.tsx`.
- Scroll-depth tracker, `TrackView`, article read-depth charts.
- Conversions, upsell panels, lead Trace, live route, ad analytics, search analytics, peak hours.
- Impersonation exclusion and deploy-gap column retry (hellokahwin has neither impersonation nor a deploy-before-migrate gap to guard).
- Importing Google Search Console history (service account lost access), adding GA, any third-party analytics.
- Retention/purge automation. Consent-banner changes.

## Success signal

After the deploy, an admin opens `/admin/site-analytics` and sees today's real visitors from hellokahwin.com by page, source, country and device, with bots filtered out, within ten minutes of the traffic happening, and no job ran to make that true. A deliberate visit to `https://hellokahwin.com/?utm_source=autopilot-verify` is visible in the UTM and Top pages panels of the same dashboard.

## Assumptions

- A first-party anonymous cookie plus a salted, daily-rotating hash does not change the site's PDPA posture or require a consent banner (same stance twn-new ships with).
- hellokahwin's event volume stays far below the scale at which twn-new needed rollups (~500K rows in 30 days there). Raw date-bounded scans serve this dashboard in well under a second; the trigger to revisit is a `[analytics-slow]` log from `safePanel`, not a date.
- The admin's own browsing is counted as traffic at launch (twn-new only excluded impersonation sessions).

## Open Questions

- Retention: with no cron the table grows unbounded. Is a manual script (`pnpm analytics:purge --older-than 730d`) acceptable as the mechanism, and what horizon?
- Should allowlisted admins' own visits be excluded from pageviews (e.g. by a cookie set on `/admin` login)?

Additive-only: yes. No existing table, column or index is touched. Applied with `pnpm db:migrate` against `DATABASE_URL` as part of the ship step, before or after deploy in either order (the collect route 500s harmlessly, and the tracker swallows failures, if a beacon lands before the table exists).

### How the dashboard stays fast without rollups

1. **Date-bounded, sargable predicates.** Every query has `created_at >= $start AND created_at < $end` on the bare column, with bounds computed from KL days (`klWindow`), so `idx_analytics_events_created_at` (or a composite starting with the filter column) serves every panel. Range is capped at 366 days; there is no "All time".
2. **One scan per panel, one scan for top stats.** Top stats materialises the scoped rows once and derives sessions and distinct visitors from that CTE. Dimension panels are a single `GROUP BY` over the scoped rows.
3. **Caching.** `cached.ts` wraps each getter in `unstable_cache` with `revalidate: 600` and tag `site-analytics`; args (range, traffic, page, country, region) form the key, so the default view is warm for everyone for ten minutes.
4. **Bounded fan-out.** `page.tsx` runs the 16 getters through `runBatched(…, 4)` (below the pool width of 5) and each through `safePanel` (6s deadline, 4s slow tripwire, transient errors degrade to an empty panel).
5. **Scale guard.** When `[analytics-slow]` warnings appear in Vercel logs, that is the signal to revisit (follow-up: rollups would need a scheduler, which this project forbids today; a materialised view refreshed on admin visit is the no-cron alternative).
