- (note) Repo facts: Next 16.1.6, Drizzle 0.45 + postgres-js (max 5, 8s timeouts), zod 4, vitest 4, Clerk allowlist auth (requireAdminSection ignores section), migrations hand-numbered 0000-0004 under src/lib/db/migrations with meta/_journal.json, RLS enabled with no policies per 0001. - (capability) CAP-1 collect endpoint POST /api/v1/analytics/collect: zod batch 1-50, IP rate limit 120/min, 8s DB deadline, maxDuration 15; no impersonation check, no deploy-gap retry, no city estimation.
- (capability) CAP-2 client tracker keeps track(event, props) signature; adds init/trackPageview/flush with 5s batching + sendBeacon; AnalyticsTracker mounted in (public)/layout.tsx as a Suspense sibling; skips /draft/*; framed-context guard kept.
- (capability) CAP-3 identity: daily-rotating sha256(ip|ua|KL-day|ANALYTICS_SALT) visitor hash; anonymous first-party _hk_vid cookie (2y, Lax, Secure, not httpOnly) minted client-side and read server-side only; raw IP never stored.
- (capability) CAP-4 bots: port bot-list.ts classifier; rows stored with is_bot/bot_reason; dashboard defaults to humans with humans/bots/all toggle and counts.
- (capability) CAP-5 geo from x-vercel-ip-* headers (country, region code, city decoded, lat, long); cf-ipcountry fallback kept; no cities15k estimation.
- (capability) CAP-6..CAP-12 dashboard at /admin/site-analytics: top stats with previous period, time-series chart, sources/UTM medium/UTM campaign, top/entry/exit pages with resolved titles and page search, countries->states->cities, browsers/OS/screen sizes, KL date-range picker; CAP-13 nav entry; CAP-14 migration 0005 with RLS; CAP-15 performance without rollups.
- (decision) Device parsing moves server-side (ua-parser-js in the collect route on the UA header) instead of the client, so the public bundle gains no parser; client sends only screen_width. Reason: public site has a strict byte budget for low-end Android.
- (decision) Visitor hash rotates on the Asia/Kuala_Lumpur calendar day, not UTC: the dashboard buckets by KL day, and a UTC rotation at 08:00 KL would split one morning visitor into two uniques.
- (decision) No middleware change for the visitor cookie: the tracker mints _hk_vid client-side before its first flush; public HTML stays cache-friendly and the Clerk matcher is untouched. Collect route is outside the Clerk matcher by construction.
- (decision) Date-range picker is simplified to preset chips + two native date inputs (no react-day-picker/Calendar). Range capped at 366 days; no 'All time' option, so every query stays date-bounded.
- (decision) Region names: small static ISO 3166-2:MY map (16 subdivisions) with raw-code fallback; iso-3166-2 package not added. Reason: Malaysian audience; the package is 244KB for one lookup.
- (decision) cities15k.json (1.39MB) city estimation is OUT: backfill-oriented, heavy on the hot path, and hellokahwin has no history to backfill.
- (decision) Not ported: 404 capture route/table, scroll-depth tracker, TrackView, conversions/upsell/lead Trace/ads/search panels, rollup tables and refresh. Each is either a TWN business feature or an event with no consumer in this scope.
- (decision) Page search uses ILIKE only (no pg_trgm word_similarity): no extension dependency, corpus is small.
- (decision) Indexes: created_at; (pathname, created_at); (session_id, created_at); (country, created_at). All queries compare the bare created_at column against half-open UTC bounds derived from KL days.
- (decision) Freshness: unstable_cache 10-min TTL keyed by filters, runBatched concurrency 4, safePanel 6s deadline per panel; cold render fan-out never exceeds pool width.
- (constraint) Hard: no cron/scheduled job/GitHub Action (commit 4e8aaaf). Migration additive-only. New table gets ENABLE ROW LEVEL SECURITY with no policies. ANALYTICS_SALT must exist in Vercel before ship; missing salt -> 503 analytics_unavailable, never an unsalted hash.
- (assumption) A first-party anonymous cookie plus salted daily hash needs no consent banner change on the Malay public site (PDPA posture unchanged from twn-new).
- (assumption) hellokahwin traffic stays well under ~5M events/year, so raw date-bounded scans serve the dashboard in under a second; a rollup revisit is a follow-up trigger, not a launch requirement.
- (question) Retention: with no cron, analytics_events grows unbounded. Is a manual purge script (e.g. pnpm analytics:purge --older-than 730d) acceptable as the retention mechanism?
- (question) Should the admin's own browsing be excluded from pageviews? twn-new only excluded impersonation sessions; hellokahwin has no equivalent. Proposed: no exclusion at launch.
