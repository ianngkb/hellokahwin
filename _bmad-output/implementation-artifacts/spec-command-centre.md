# Spec — The HelloKahwin Command Centre

One internal, self-contained, regenerate-on-demand HTML dashboard, generated by a
dependency-free Node script that reads the REAL files and the LIVE Search Console API.
Nothing on the page is hand-written data.

## Non-goals
- No production deploy. Internal artifact; public exposure needs board approval.
- No push to `origin` (it is the live-site repo; local history is diverged).
- No npm dependencies.

## Inputs (all real)
| Source | Path | Yields |
|---|---|---|
| Boardroom | `docs/boardroom/` | ceo-memory, decision-log, meetings/*.md |
| Plans | `docs/plans/<session>/*.md` | plans, briefs, research, audits, proposals + Status |
| Work done | `docs/work-done/<session>/*.md` | completion records + evidence |
| Org chart | `<skillcentral>/agents/projects/hellokahwin/**/*.md` + CHANGELOG.md | personas, departments, hire dates |
| Cluster plan | `aug-23-2026-clusters-launch-plan.md` | 7 pillars, 26 clusters, 204 topics, tiers |
| Workflow | `aug-23-2026-workflow-content-production.md` | 8 article stages, 6 pillar steps, team ownership table |
| Growth plan | `aug-23-2026-plan-malay-topical-authority.md` | checkpoint table (30/60/90d), revision history |
| Search Console | `searchconsole.googleapis.com` via service account | clicks, impressions, CTR, position, daily series, top queries/pages |

## Chunks
1. **md.mjs** — zero-dep markdown→HTML: headings, tables, fenced code, blockquotes,
   nested lists, hr, bold/italic/code/links. Tables are mandatory.
2. **docs.mjs** — walk the tree; per doc: title, `**Key:** value` meta block, date,
   session, owner, status (normalised DRAFT/APPROVED/SUPERSEDED/ABANDONED/DECISION/INFO),
   revision history, supersedes/superseded-by, sections, body HTML, mtime, word count.
3. **decisions.mjs** — parse `decision-log.md`: `## <date> — <group>` + numbered `N. **claim** …`;
   split out Basis / Prediction / Consequence; extract prediction due-dates
   (`@30d`, `by 21 Nov 2026`, `next meeting`); attach outcomes from an optional
   CEO-owned `docs/boardroom/prediction-outcomes.md`; score GSC-measurable predictions
   against live data. No outcomes file → honest "not yet scored", never a fake outcome.
4. **org.mjs** — parse agent frontmatter + body: reports-to, hired-on, blocking authority;
   department = folder; owns/cannot-do from the workflow team table; activity = plans and
   work-done attributed to that agent; full persona rendered in-page.
5. **clusters.mjs** — pillars (`### P<n>.`), clusters (`#### C<x>.<y>`), topic counts,
   volumes, tiers; coverage % = articles live ÷ topics mapped.
6. **pipeline.mjs** — 8 article stages + 6 pillar-opening steps with owners and gates;
   article cards placed by stage; pillar readiness per pillar.
7. **derive.mjs** — timeline events; blocked items (DRAFT status, `## Follow-ups`,
   `What I need from…`, `Owner requests`, open meeting actions); approvals queue with
   waiting-days; weekly article count; "changed since last visit" via mtime.
8. **gsc.mjs** — RS256 JWT → OAuth token → searchAnalytics.query. Totals 28d,
   prior 28d, daily 120d, top queries, top pages. Snapshot cached to
   `docs/dashboard/data/gsc-snapshot.json`; `--offline` reads cache. Failure is
   reported ON THE PAGE, never faked.
9. **render.mjs + assets** — single HTML file: sticky nav, 10 sections, filters
   (session/owner/status/type), global search, expandable rendered documents,
   SVG charts, CSS org tree, dark/light, mobile-first responsive.
10. **generate.mjs** — CLI: `--offline`, `--out`, `--open`, `--quiet`. Prints a
    source-coverage summary so a stale run is obvious.

## Acceptance
- Every one of the 6 required sections present and populated from real files.
- Brainstorm 1 (clusters), 2 (pipeline), 5 (blocked), 9 (approvals) present. 10 (search)
  and 11 (what changed) included as cheap wins.
- Every persona `.md` readable in-page; org chart shows reporting lines, departments,
  and the verification lead's blocking authority.
- Zero hardcoded metrics. GSC numbers carry their pull date; an unreachable source
  renders an explicit failure card.
- Empty sections say plainly that they are empty and why.
- Regenerates with one command; page renders on a phone.
- No secret is printed, logged, or committed.
