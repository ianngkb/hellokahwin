## What was decided before writing

### The cover-path convention: relative to the article file, no `./`

**Same convention as the P1/P6 run, and it was already satisfied.** All twelve
image references across the nine files are bare relative paths — a sourced
photograph as `images/S-name.jpg`, no `./` anywhere. Audited, not assumed:

```
=== './' prefixes in the nine files: 0 ===
=== image references: 12 declared, 12 resolved on disk (after Blocker 1 removed the 9 phantoms) ===
```

The convention is stated in `src/lib/inspire/article-file.ts` on
`imageSchema.file` and in Stage 7 of the workflow. Nothing was edited to comply.

**One mechanical consequence of staging, stated so nobody diffs for it.** The
staging copies live one directory below the originals, and `resolve()` is
relative to the **article file**, not the drafts root — so `images/S-x.jpg` in a
staging copy resolves to `drafts/ingest/images/`, which does not exist. The
staging copies therefore carry `../images/S-x.jpg`.

This changes nothing that reaches the site, and that was verified rather than
assumed. The R2 key is the declared path slugified — every run of
non-alphanumerics collapsed to one hyphen, leading hyphen stripped
(`ingest-article.mts:563-570`) — so `../images/S-x.jpg` and `images/S-x.jpg`
both derive `images-s-x`. The keys written this run prove it:

```
inspire/ucapan-pengantin-baru/1787654608921-images-s-tetamu-tiba-majlis-ahmad-ali-karim.jpg
inspire/cincin-tunang/1787654724064-images-s-kuku-berinai-pengantin-azman-aziz.jpg
```

Byte-identical in shape to the P1/P6 batch's keys. No `-` prefix, no `..`.
