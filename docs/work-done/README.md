# `docs/work-done/` — the record of a change, next to the change

Every shipped item leaves an entry here with evidence a reader who was not
present can re-run. This file is the index of indexes; it is not a place to put
an entry.

## Where your entry goes

**In the session directory, not here.** The convention since
`aug-28-2026-session-01` is one directory per working session, each with its own
`README.md` carrying a table of that session's items. Append a row to that table
when you ship; do not edit this file for an item.

| ------------ | ---------------------------------------------------------------- |
| `-EVIDENCE/` | before/after captures, raw instrument output, measured numbers    |

## This file exists because its absence kept being reported as a finding

Every sprint's standing rules say *"update `docs/work-done/README.md`"*. Until
UI-19 it did not exist, and three separate agents — PLAT-19, DES-18 and this
item — each reached that instruction from a fresh worktree, went looking, found
nothing, and filed the same open finding for the CEO. Three reports of one
missing file is three reports more than it costs to write it.

It is deliberately an **index and a convention statement**, not a log. A single
flat log across every session is the thing the per-session directories replaced,
and re-creating one here would give the same information two homes to drift
between.

## Which branch this lives on

**`master`.** `docs/work-done/**` is site space, alongside the diff it
describes, so a reviewer reading the change can reach the record of it. That is
the path map in [`scripts/git-hooks/README.md`](../../scripts/git-hooks/README.md),
which supersedes the older blanket rule that *anything* under `docs/` belongs on
the docs line — a rule UI-13 measured and found wrong. `docs/plans/**` and
`docs/design/des-*` are the company record and do belong on
`feat/command-centre-dashboard`; these entries do not.
