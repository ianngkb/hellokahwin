## 1. The register

CSV, in git, outside the CMS. Chosen because it opens in a spreadsheet for the
person maintaining it, diffs line by line so an edited provenance shows up in
review, and parses anywhere. Those three are the whole requirement.

**700 rows.** 682 inherited items, generated by direct parse of
`data/hellokahwin-export/content/media.json`, plus the 18 C2.4 assets.

### How it says "we don't know"

Three sentinels, not one, because they are three different states:

- `TIDAK DIKETAHUI` — we looked and it cannot be established. A finding.
- `BELUM DIISI` — nobody has looked yet. A task.
- `TIDAK BERKENAAN` — the field does not apply to this class of asset.

Collapsing these into one value quietly closes tasks. A coordinator who writes
`TIDAK DIKETAHUI` where they mean `BELUM DIISI` has decided, without saying so,
that nobody needs to check.

### How it cannot drift from the code

The licence classes were read from the parser, not guessed:

```
// src/lib/inspire/article-file.ts
export const LICENSE_CLASSES = ['V', 'C', 'O', 'S', 'G'] as const;
```

The parser trims and upper-cases before checking, so `v` and ` V ` pass and
anything else refuses the whole file.

**The register adds a sixth value, `TIADA`, and it is deliberately one the parser
will reject.** It means no licence class can be assigned because no licence
exists. An asset carrying it cannot pass ingest, which is the correct outcome.
There is no way to describe an unlicensed image in this register in terms the
publishing path will accept. That is the design, not a gap in it.

### What it says about the inherited library

All 682 carry `license_class: TIADA`. 401 are `kuarantin` (Real Wedding, class A,
do not publish and do not delete). 281 are `jangan-guna`. 120 carry a creator name
the file itself asserts, recorded with `bukti_pencipta` naming which EXIF field it
came from. Every `licensor_name` reads `TIDAK DIKETAHUI`.

A name in `pencipta` is a lead for the clearance programme. It is never promoted
to `licensor_name` without evidence in `bukti_lesen`.

## 2. The licence template

Two templates in each language. **A** for images we have not published. **B** for
the ten Real Wedding studios whose work is already on the site.

**Scope is narrow on purpose**, and this is where I departed from the strategy
(see finding 4 below). What is asked for: publish the named images on
hellokahwin.com and HelloKahwin's own social accounts, resize and crop for layout,
credit as the licensor words it, followed link. What is explicitly not asked for:
ownership, exclusivity, resale, sub-licensing, paid advertising, AI training.
Withdrawable by one email, five working days, no reason required.

The retroactive letter says what happened rather than dressing it up. It states
that credit was given, that no written permission was found, that a credit is not
a licence, and that the situation is unclear. It offers take-down first, before
the two options we would prefer, and says plainly that take-down is a real option
rather than one we are hoping they will not choose. It also flags that the
photographer's permission alone is not enough for identifiable people and that we
will approach the couple separately.

**Nothing has been sent.** Contacting real people is the owner's decision.

Both letters went through `/humanizer` after they were written. The pass removed
every em dash from both and left the short emphatic lines alone: *Kredit bukan
lesen* and *A credit is not a licence* are load-bearing claims, not rhetoric.

## Findings where reality contradicted the strategy document

**1. The count is 18, not 19.** Ten in-article markers across the eight drafts,
not eleven. I could not reconstruct a nineteenth and did not pad to reach it.

**2. The strategy under-reports the EXIF problem, and one item is worse than it
says.** Strategy §1.3 states *"96 of 682 items (14%) carry a third-party copyright
or credit string in EXIF"* and names six owners. Re-parsing the same file: 96 is
the count for the EXIF `credit` field alone. **106 items carry a `copyright`
field, and 120 carry one or the other, across 30 distinct owner strings**, not
six. Among the 24 the audit did not surface: `Getty Images/iStockphoto`,
`© 2025 Jessielyee Photography, all rights reserved.`, `Adam Ong Photography`,
`MUNKEAT STUDIO`, `TRBAN PHOTOGRAPHY`, `Dbrothers Studio`, `Jackie Yong
Photography @ 2019`.

A named commercial stock library's copyright string on an image we cannot
demonstrate a licence for is a different class of problem from probable vendor
marketing imagery. All 120 names are now in the register with the EXIF field they
came from.

Everything else in the census reproduced exactly: 682 items, 401 `RW-`, 269 `IN-`,
12 other, 312 with camera EXIF, 38 with alt text, 6 with captions.

**3. The strategy asks for SVG. The pipeline will not keep one.**
`generateVariants` encodes every variant with `.webp({quality})` unconditionally,
and ingest derives `mime_type` from the file extension. An SVG handed to ingest is
rasterised by sharp using the build box's fonts. The spec's answer: author in SVG,
rasterise to PNG deterministically with fonts embedded, hand ingest the PNG.

**4. The brief and the strategy want different licences, and I followed the
brief.** Strategy §2.4 proposes *"a non-exclusive, perpetual, worldwide licence."*
The brief says *"Do not overreach. Ask for what we need to publish an article, not
a perpetual worldwide transfer."* I wrote the narrow one. An easy yes we can rely
on beats a broad grant nobody signs, and a revocable licence is one a photographer
can say yes to in a single reply. Flagging it because it is a real reversal of an
approved strategy document, not a wording preference.

**5. The brand palette exists. The document that ratified it does not.**
`src/app/globals.css` carries a complete token set under *Design System v2 "Plum
Forward"*. Ten code comments cite `DESIGN.md` as the ratifying authority and no
`DESIGN.md` exists in the site repo, either worktree, or this one. Tokens are the
source of truth because today they are the only source.

**6. There is no brand chart palette.** `--chart-1` to `--chart-5` are shadcn's
stock defaults, unmodified — an orange, a teal, a blue, two ambers. They clash
with plum and brass and nobody chose them for HelloKahwin. **I did not invent a
replacement.** It does not block C2.4, because none of the three needed templates
plots multiple series. It will block the cost band chart when P6 arrives.

**7. The site has no fixed typeface, so a graphic has nothing to match.**
`globals.css` line 25: *"HelloKahwin serves system font stacks — zero webfont
bytes."* Geist and Geist Mono load through `next/font` in the `(admin)` console
layout only. The public site renders in a different face on every device. Since a
rasterised graphic cannot use a system stack at all, the spec picks Geist and
Geist Mono on stated criteria (already in the codebase, SIL OFL so the class G
font-licence requirement is one line, and Geist Mono gives the tabular figures a
ringgit column needs) rather than on taste.

**8. Only covers go through smart crop.** Every render call site reads crops from
`article.coverImageSmartCrops`. Body images render from `variants` at their own
aspect ratio. So an in-article table can be as tall as it needs to be, and a cover
can carry almost no data. This is the most useful single fact for whoever builds
the kit and it is not in any strategy document.

**9. Three field vocabularies describe the same asset.** The parser wants
`credit` / `creditUrl` / `licenseClass` / `licensorName`. Style guide §13.2 wants
`nama pemilik` / `jenis pemilik` / `URL sumber asal` / `status kebenaran` /
`tarikh diperoleh`. Strategy §3.2 lists ten fields in a third wording. All ten
approved drafts use the style guide's set, so they carry field names the parser
does not know. The register README §3 reconciles them: any column feeding the
parser carries the parser's own name.

## Assumptions I made, since the brief said to make the calls

1. **CSV over YAML or JSONL** for the register. A spreadsheet is what the strategy
   itself calls this artefact, and the person who will maintain it is not a
   developer.
2. **English column names where a column feeds the parser**, Malay values
   throughout. Mixed naming invites drift, and the join between register and code
   is by name.
3. **The register carries rows for assets that do not exist yet**, at
   `status_guna: belum-dihasilkan`. It doubles as the production queue, which is
   how the 18 outstanding graphics became countable.
4. **`TIADA` as the unlicensed sentinel**, chosen specifically because the parser
   rejects it.
5. **A seventh template.** The brief named six and six cannot produce a cover.
6. **Build three templates now, defer three.** Named in the spec §5 with the
   cluster each deferred one belongs to.
