7.3  The three loading layers

Named once so no two components invent their own timing. 0–300 ms: nothing renders — a flash of a skeleton under 300 ms reads as flicker, not feedback. 300 ms–3 s: the skeleton, --skel blocks matching the true height of what is loading, so the page does not jump when content arrives. ≥3 s: a 2 px --accent bar plus “Sedang dimuatkan…” in an aria-live="polite" region, so a slow connection is told something is still happening rather than left looking broken.

7.5  H6 — the homepage diversity rule, written so it can fire

What this corrects, and why it is a defect in this document rather than in the build

§5.3 asserted a diversity rule and sent the reader to “H6 in §7”. No rule H6 existed. Every word-boundary H6 match in this artifact was three base64 fragments inside embedded WebP data plus the cross-reference itself, and §7 carried the word diversity zero times and categor zero times. The rule was asserted, drawn, and never written, so nobody could have built it and nobody could have failed to build it. Sprint 04's finding applies exactly: the parts of this document written as enforceable constraints shipped, and the parts written as prose and a drawing did not ship at all — same document, same author, same sprint. H6 is therefore written below as a constraint with an extraction rule, a tie-break, a fallback and a checker script, not as a sentence about variety.

The homepage H namespace, resolved, so the next reference does not dangle the way this one did. §7.1 counts eight homepage states; only three carry an id anywhere in this document. The other five are the palette × breakpoint × length variants drawn in §5.3 and are deliberately unnumbered. Do not invent H2, H4, H5, H7 or H8: a new homepage state takes the next free number and is registered in this table on the way in.

IdWhat it denotesWhere it is defined
H1The homepage default — hero, then the rowsDrawn in §5.3 at 360 px and 1200 px, both palettes
H3The no-hero variant: no article in the corpus carries a class O or class P cover, so the homepage opens on rows rather than enlarging a frame §6 disqualifiesRuled in §5.3, class gate in §6.3, invoked as the last step of H6.5 below
H6The category diversity rule — a constraint on the homepage item set, not a state of itBelow, and executable as scripts/measure/check-h6.sh

H6 — homepage category diversity. Normative.

H6.0 — the set, and how it is extracted. The homepage item set is every article link the homepage renders, in DOM order, deduplicated by path with the first occurrence winning. An article link is an href matching /artikel/<kategori>/<slug> — exactly two path segments after /artikel/. A one-segment link is a category link and is never an item, which is what keeps the masthead, the breadcrumb and the footer out of the count. An item's category is <kategori>. Nothing else is consulted: no data attribute, no CMS field, no heading text. s[1] is the hero, N is the number of items, and cap = ceil(N/3).

H6.1 — share cap. No category supplies more than cap items. At N = 13 the cap is 5.

H6.2 — run cap. No two consecutive items share a category. Maximum run length is 1.

H6.3 — distinct floor. The set names at least F = min(4, K, N − cap + 1) distinct categories, where K is the number of categories holding at least one published article. The third term is not decoration: without it H6.3 contradicts H6.1 at small N, because a floor above N − cap + 1 forbids any category from reaching the cap H6.1 explicitly permits. At N = 4 the floor is 3, not 4. That contradiction was in the first draft of this clause and was caught by the pass-short.html fixture, not by reading it.

H6.4 — the tie-break, because recency alone does not order this corpus. Slots are filled 1 to N. Slot 1 takes the highest-ranked article whose cover is class O or class P (§5.3, §6.3); no H6 clause can bind at slot 1, so hero eligibility and H6 cannot conflict there. Every later slot takes the highest-ranked remaining article that keeps H6.1 and H6.2 true. Rank, applied in order until one comparison decides: (1) published date, most recent first; (2) then the number already placed from that article's category, fewest first; (3) then category slug, ascending byte order; (4) then article slug, ascending byte order. Every comparison is total, so one corpus always yields one set. This clause is load-bearing: on the sitemap of 01 September 2026, 24 articles carry one identical timestamp and 19 carry another — rank 1 alone leaves 24 items unordered and the homepage non-deterministic. Rejected: ranking diversity first, that is (2) before (1). It produces a well-mixed homepage that buries what was published yesterday, and §5.3 gives the homepage the job of being the record of what is new. Diversity is a constraint here, not a preference.

H6.5 — the fallback, when the corpus cannot satisfy it. H6.1 is satisfiable at a given N if and only if Σx min(published(x), cap) ≥ N. H6.2 is then satisfiable automatically, because cap = ceil(N/3) never exceeds ceil(N/2), the multiplicity above which no arrangement can avoid adjacency. One test therefore decides the whole question. If it fails, relax in this fixed order, one step at a time, never further than the slot requires: (1) relax H6.2 for that slot only — a run of 2 is permitted, a run of 3 never is; (2) then relax H6.1 for that slot only, cap + 1, and return to step 1 for the following slot before spending another +1; (3) then truncate — render a shorter set. The homepage is valid at any N ≥ 4. Never repeat an article and never pad to reach a target length. (4) Below N = 4 the homepage runs H3, the no-hero variant; with zero published articles it renders .s-empty (§8), not the blank page §7.4 records shipping. The order is deliberate: an adjacent pair is monotony, one category owning the page is the failure §5.3 measured. Monotony is the cheaper thing to spend, so it is spent first.

H6.6 — DOM order is the order. H6 is measured on DOM order, which is also tab order and the order a screen reader announces. Homepage items may not be visually reordered away from source order — no order, no grid-auto-flow: dense, no *-reverse on the item container. A page that satisfies the checker while reading in a different sequence to a sighted reader has satisfied nothing.

H6 needs no build input this document does not already have. §12 names “category counts available at render time” as an unresolved build dependency. H6 does not touch it: an item's category is in its own URL, so the rule is evaluable on the rendered page today, with no CMS change and nothing added to the markup.
