09

Heading hierarchy and schema slots

These are design decisions, not implementation detail, and this section is what head-of-seo-content reviews before this document is treated as the spec. Every heading level below is tied to a visual style already drawn in §5; none is invented to satisfy an outline that has no corresponding block on the page.

9.1  Heading levels, one page at a time

PageLevelUsed forStyle
Articleh1The article title. Exactly one per page..s-h1
h2Named article sections — “Kadar minimum mas kahwin mengikut negeri” and its siblings. One per contents-list entry..s-h2
h3–h4Sub-points inside a section. Not used as a styling shortcut — a bold paragraph lead is not a heading..s-h3
n/aRekod panel labels, table headers, credits: never a heading level. They are metadata about the article, not the article's structure..s-label
Catalogueh1The category name. Exactly one..s-h1
h2Each row/card title within the list — the article's own headline, marked up as a heading because a catalogue is a list of documents, not a list of links. This is why §5.2's list rows use <h2 class="t"> rather than a bare span..t
Homepageh1Not the wordmark — the wordmark is a link, not a heading. h1 is the hero article's own headline..s-h1
h2Terkini and each subsequent section label..s-label
h3Each row/card title within a section, for the same reason as the catalogue..t

One correction this makes to what §5 drew

§5.2 and §5.3's list-row titles are marked <h2 class="t"> and <h2 class="t"> respectively in the source, but a homepage row sits inside a page whose own h1 is the hero — those rows must build as h3, not h2, or the homepage carries two h2 levels with no h1 between the second and the page title. This is a markup correction the DSE applies during the build; the visual style .t is unaffected.
