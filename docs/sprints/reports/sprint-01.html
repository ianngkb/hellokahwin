Database migrations — test these first

Three migrations went to production

Sprint tracker tables — 20260825120000_sprint_tracker.sql and 20260826090000_sprint_backlog.sql on buddy: two new tables plus a nullable column. Additive only; no existing buddy table was altered.

The hellokahwin content database took writes all sprint — 5 new articles, 69 images, 68 internal links, one fee-table swap. Every one of those writes happened after a verified restore path existed, which was the whole point of running RISK-01 first.

These are listed first because they are the ones that can break production in the gap between a deploy and a migration. Nothing waived a gate this sprint — there is no waived-check band below because there was nothing to put in it.

What shipped, item by item

Thirteen items. Each one says what changed in plain terms, and how to check it yourself.

RISK-01

The site can now be restored if the database is lost

5 pts

Until this sprint, if the content database had been deleted or corrupted there was no way to get it back — no backups of any kind. There is now a nightly copy stored separately, it has been proven by actually restoring it, and if a night ever fails, a ticket is filed automatically within ten seconds.

How to check itOpen the repository's Issues tab on GitHub. Two closed tickets titled "ALARM: hellokahwin production DB backup…" are there from the test — one of them was a real failure the alarm caught before anyone knew to look for it.

PLAT-01

A sprint board you can open and use

8 pts

Sprint work used to live in a text file only one person could read. It is now a board with every task, who owns it, what "done" means for it, and the evidence that it was done — the same information whether you look at the website or run it from the command line.

How to check itGo to buddy.ian.ng/sprints (sign-in required). You will see all fourteen tasks grouped by type. Drag one to a different column and it stays moved.

PLAT-04

Planning the next sprint, and seeing how the last one went

5 pts

The board now holds a backlog of things not yet started, a history of past sprints with how much each actually finished, filters to see only your own work, and the retrospective shown next to the sprint that produced it.

How to check itOn the same page, look for the backlog panel — it currently holds one item, the document-reading feature. The history row shows Sprint 01 as 42 planned, 40 completed, 2 parked.

PLAT-02

New articles appear immediately instead of after a five-minute wait

2 pts

When an article was published, the section page listing it could keep showing the old version for up to five minutes — long enough for Google to arrive and see nothing there. Publishing now clears that instantly.

How to check itThe three newest articles under hantaran-mas-kahwin appeared on that page the moment they went live. Previously they would have taken five minutes.

SEO-02

The site stopped telling Google to ignore its own links

3 pts

Seventy-nine links between our own articles carried a hidden instruction telling Google not to follow them — while we were investigating why twenty articles had never been visited. Thirty-two articles also had nothing linking to them at all. Both fixed: sixty-eight new links added, every one pointing at an address Google recognises.

How to check itOpen any article and scroll to the related-reading section at the bottom. Every article now has one, and every article is linked to from somewhere else.

Time, models & tokens

Not measurable for this sprint, and that is a finding

The generator that produces this card reads /buildit's ship-log to find a batch. A sprint does not write one, so it returns an empty card rather than a number. Its own output: "no ship-log entry found; emitting empty card."

Rather than fake itThe honest position is that effort per stage was not captured for Sprint 01. Making run-stats.py understand a sprint — or having /startsprint write the ship-log entry the tool expects — is carried forward as a candidate. A partial number presented as a total would be worse than this paragraph.

The retrospective

Held with Winston, Murat, the Managing Editor, the Head of SEO and the writer. Every finding below names the file it changed — a lesson with no target file evaporates.

Three items were marked done without being shipped, and the owner found all three by asking

PLAT-01 and PLAT-04 were built, committed and tested — and never merged. origin/main was unchanged; the board did not exist. CONT-02's sixty-nine images sat in draft files. The paper trail sat at 161 uncommitted files and 14 unpushed commits.

Not one was caught by a check. The ship check existed — it was written the day before and caught a real gap on its first run. Then it was not run again.

Murat's verdict, which is the sentence worth keeping: "Not that we lacked a check — we HAD one, and running it was left to memory. A gate you have to remember is a suggestion."

The ship check is now a refusal, not a reminder

skillcentral/skills/startsprint/SKILL.md

Marking an item done is now defined as an assertion that the three checks have just been run for that item — working tree, unpushed commits, and the user-visible surface. If you cannot name what you checked, you do not mark it done.

The visual-build stage ended at a draft, so its author could forget the last step

docs/plans/…/aug-23-2026-workflow-content-production.md

The Managing Editor named it exactly: "in my head 'the draft is finished' and 'the work is finished' are the same sentence." The Head of SEO named why it bit this stage and no other: ingesting is a writer's last step, so a writer cannot forget it — this stage ends in a file, so its author can. The gate is now production, not the file.

A rule repeated in briefs belongs in the artefact

agents/projects/hellokahwin/Editorial/writer-*.md

The same instruction — never leave placeholder image markers — was written into two separate briefs for the same writer. It is now a format error, malformed the same way a missing required field is malformed, rather than something a brief has to keep asking for.

On a sign-in-protected site, a status code cannot prove a page exists

skillcentral/skills/hellokahwin/SKILL.md

Every path returns the same redirect, real or invented, because sign-in happens before routing. Two of the three unshipped items passed review on exactly that. Proof must come from the page's content, with a control that lacks it — and when it genuinely cannot be verified from outside, say so and hand over a URL.

Handles assigned by reading a list in order — wrong in both directions at once

skillcentral/skills/startsprint/SKILL.md

Two tasks were given two workers each on the same instructions; two others never started, including the one everything else was waiting behind. Capture the identifier at dispatch and audit it before reporting progress — a task that silently never started produces no error anywhere.

Two rules the CEO wrote were disproved by the team, and both times the team was right

docs/boardroom/ceo-memory.md

Moving old articles needs no redirects; and the rule for comparing old and new addresses was comparing one old address to a different old address. Both corrected at source rather than noted in a log.

What went right, and must not be mistaken for luck

When two workers were mistakenly given the same task, both stopped rather than racing and asked who owned it. Publishing overwrites whole files, so a race would have silently published the loser's version. The one that stood down reviewed the other's work on its way out and found a real defect — a comment claiming a credential had been verified when it had not.

Winston's warning stands: do not congratulate the fleet for surviving a dispatch error — fix the dispatch.
